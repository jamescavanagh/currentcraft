# 0.10.0 candidate: document API

This is preparation for an alpha release, not a tag, publication, deployment or
production-readiness claim. The coordinator approved dependency-complete hosted
Python 3.11/3.12 required HTTP tests in place of a sandbox-local full pass. Local
checks and limitations remain separate evidence. No private vocabulary-scan
exception was granted; no private term file has been supplied.

## Scope and limits

Implemented: shared CLI/API source identities; local shared-token HTTP auth;
fail-closed shell/readiness; bounded text/XLSX intake; durable first-receipt/retry
storage; worker pending/processed/quarantined status; privacy-safe opaque
project-document/task/WBS/subject reads; generated OpenAPI; nonroot API and
secret provisioner; real synthetic text HTTP upload/poll/retry Compose smoke.
A 202 means durably queued, not extracted; processed tasks are source records,
not approved or executable work. Restart-scoped read handles still require
private initial discovery; persisted intake receipt handles are separate.

Forward-version contracts/design pages already in the tree (evidence,
evaluation, release ladder, challenge/appeal and drawing lifecycle) retain their
own stated implementation limits. Bundling them does not ship their future
workflows or establish semantic/process validation. HFGT follow-ups remain
explicitly deferred; the capability graph is a structural reading, not release
authority. No removal of compatibility aliases in this candidate.

Not claimed: OIDC, public CORS, deletion/restoration, S3, ClickUp import,
simulation/HFGT HTTP endpoints, live workbook/full-read acceptance, retained
receipt replay across API-process restart, fault injection, production
readiness or comprehensive enterprise-vocabulary certification.

## Environment evidence contract (docs before implementation)

`python scripts/local_stack.py evidence` reads the already-running stack;
`smoke` invokes the same collector after its actual HTTP smoke succeeds. Existing
CI runs `smoke` before and after restarting PostgreSQL, NATS and worker, so no
workflow-file edit is needed. A failure collecting required evidence fails the
smoke instead of inventing a version or digest.

The host helper emits one `RELEASE_EVIDENCE ` JSON line with schema
`currentcraft-release-evidence/v1`, the exact Git checkout SHA and package
version, and only these allowlisted observations:

- PostgreSQL and NATS server versions from their running containers.
- Python and installed datamesh-agency-toolkit, psycopg, nats-py, FastAPI,
  uvicorn, Starlette, Pydantic and python-multipart versions in the API image.
- Actual running PostgreSQL/NATS/API image IDs plus repository digests.
  Public server repository digests must be present; an unpublished local app
  image has an image ID but normally no registry digest. Never invent one.

Collect only selected Docker inspect format fields, never full inspect,
container environment, Compose expansion, connection strings or credentials.
Capture subprocess output privately, bound each command by 20 seconds and the
whole collection by 120 seconds, validate all values before printing, and emit
only a fixed error on failures. Version strings are observations, not new pins.
Helper/negative-control tests are distinct from live Docker execution.

## Candidate verification record

Baseline before version preparation: merged main `50cf586` passed all five
hosted jobs, including real HTTP smoke before/after service restart. That is
baseline evidence, not validation of the candidate below.

Candidate-head hosted runs, exact environment snapshot and pass/skip details
will be recorded after the candidate is executed. Every run's emitted checkout
SHA identifies what actually ran; do not infer final-head success from a prior
PR, a shell-only smoke or a memory/DuckDB stand-in.

## Blocking release gate

Run `dmgov release <candidate> --terms <private term file>` outside the public
repository. Keep the term file and matched strings private; record only safe
results and provenance in the internal release record. Until this succeeds,
the candidate remains blocked from tag/release/public artifact publication.
A public branch/PR contains only the already governed public tree; it is not
comprehensive enterprise-vocabulary certification.

Before release: verify the final candidate's hosted gates, fresh public export
and private-path scan; record exact versions/digests and all run/skip/failure
results; obtain coordinator approval for any tag/release. Database/broker fault
injection remains production follow-up, not an implied result of this alpha.
